sass-themes

A generic build-time theme compiler for Sass with deterministic CSS and stable runtime custom-property hooks.

Purpose and usage

The library registers complete maps of final CSS token values, then emits themed selectors and optional custom-property declarations. It contains no palette, resolver, or design-system data.

@use 'themes';

@include themes.register(light, (
  surface: #fff,
  text-on-surface: #111,
));
@include themes.register(dark, (
  surface: #111,
  text-on-surface: #fff,
));

:root { @include themes.emit-variables(); }

.card {
  @include themes.apply(background-color, surface);
  @include themes.theme-bg-tx(surface);
}

Configuration

$selector-mode: class !default

Public string selecting the output strategy. Valid values are class and data-theme. An invalid value errors when output is requested.

$css-modules: false !default

Public boolean. When true in class mode, theme classes are wrapped in :global(). It has no effect in data-theme mode. A non-boolean value errors when output is requested.

@use 'themes' with (
  $selector-mode: class,
  $css-modules: true,
);

Registry lifecycle

The registry starts in collecting. The first successful apply() or emit-variables() changes it to sealed; theme-bg-tx() seals it through apply(). Output calls remain repeatable after sealing, but any later register() call errors.

Output requires at least one registered theme. Validation completes before state mutation or CSS output.

Canonical tokens and validation

The first registered theme establishes both the canonical token set and its output order. Every later theme must contain exactly the same keys. Input order may differ; output is normalized to the first theme's order.

  • Theme and token names are strings matching [a-zA-Z_][a-zA-Z0-9_-]*.
  • Each theme receives a non-empty map and may be registered only once.
  • Values may be any final CSS value except null, including false, 0, quoted strings, lists, shadows, borders, families, keywords, and functions.
  • Missing, extra, invalid, duplicate, or late registrations error without changing the registry.

Selector modes

ConfigurationDescendantSame element
class.light .card.light.card
class + CSS Modules:global(.light) .card:global(.light).card
data-theme[data-theme="light"] .card[data-theme="light"].card

$same-element: false selects the descendant form; true selects the joined form. In data-theme mode only attribute selectors are emitted.

Public API

register($theme, $tokens)

Mixin · no CSS return value

$theme is the theme identifier. $tokens is its non-empty complete map of final CSS values. The first call defines the canonical schema and ordering. It emits no CSS. It errors for invalid names or maps, null values, schema mismatches, duplicate themes, or a sealed registry.

variable-name($theme, $token)

Function → unquoted string

Both required parameters are validated name fragments. Returns --theme-<theme>-<token>. Registration is not required, the registry stays collecting, and invalid fragments error.

emit-variables()

Mixin · no parameters

Emits every registered custom property, in theme order then canonical token order, directly into the current scope. It creates no selector and seals the registry. It errors for invalid configuration or an empty registry.

apply($property, $token, $before: null, $after: null, $same-element: false)

Mixin

$property is the CSS property and $token is a registered canonical token. Optional values $before and $after are space-separated around the themed value. Boolean $same-element selects joined rather than descendant selectors.

For every theme, emits a scoped rule containing the static declaration followed by its runtime var() declaration, then seals the registry. It errors for invalid configuration, no themes, an unknown or invalid token, or a non-boolean $same-element.

theme-bg-tx($token, $before-bg: null, $after-bg: null, $before-color: null, $after-color: null, $same-element: false)

Mixin

Convenience wrapper applying background-color from $token and color from the canonical text-on-<token> token. The four optional part parameters surround their respective themed values; $same-element is passed to both apply() calls.

It emits both sets of themed rules and seals the registry. It has the same output validation errors as apply(), and also errors when the derived text token is absent.

Static fallback and runtime variables

Each apply() declaration is emitted twice: first with the registered static value, then with var(--theme-<theme>-<token>, <fallback>). Browsers without a supplied custom property retain the same registered value.

.light .card {
  background-color: #fff;
  background-color: var(--theme-light-surface, #fff);
}

Runtime values can be replaced through declarations emitted by emit-variables(), inline styles, or more-specific consumer rules.

Call ordering and variable scope

After all themes are registered, either output mixin may come first. Calling apply() before emit-variables(), or vice versa, produces the same contracts; both may be called repeatedly after sealing.

The consumer owns custom-property scope. emit-variables() emits declarations but no selector, so include it inside :root, a preview container, or another intentional scope. It may be omitted because every runtime reference has a static fallback.

Migration
